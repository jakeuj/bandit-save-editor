# 遊戲與編輯器 UI 驗證操作手冊

## 適用範圍與證據

本手冊補足 computer use 的操作與驗收脈絡；精確公式、SID 與來源指紋仍以研究文件為準。現有 v2.3 的 380 組效果、76 次洗練證據來自隔離遊戲原生函式及存檔 IO，並非 380 次滑鼠操作。尚未建立完整遊戲選單的畫面導覽，不得把下列待驗流程當成已完成。

| 證據 | 可證明 | 不能代替 |
| --- | --- | --- |
| 合成／核心測試 | 邊界、交易、原文保留 | 遊戲載入及 UI |
| 隔離原生函式與 IO | 公式、存檔／重啟、原生後續動作 | 選單路徑、按鈕資格與面板即時顯示 |
| 遊戲 UI 操作＋截圖 | 可見狀態、選槽限制、實際操作結果 | 未測範圍與其他版本 |
| 網頁 UI／PWA | 編輯器流程、匯出讀回、離線 | 原生遊戲 UI、直接 file:// |

## 開始遊戲 UI 測試前

1. 先讀 `docs/maintenance.md` 和對應研究，核對安裝 build、完整 13+2 來源及 repo 外隔離 state。保留原生 Steam 初始化與測試鏡像；不把正式玩家存檔當測試工作檔。
2. 先確認當次工具是否提供原生 Windows 視窗控制。有則按該工具及 computer-use 技能的實際文件操作；若只有瀏覽器能力，記錄「原生遊戲 UI 尚未驗收」，不要把透過除錯介面呼叫遊戲函式改名為 computer use UI 實測。
3. 從視窗清單以隔離程序 PID、標題與路徑辨識目標，不把正式 Steam 遊戲視窗混入。記錄遊戲版本、解析度、視窗尺寸、DPI、語言、存檔槽及初始畫面。
4. 優先沿用已相符的隔離工具建立測試資料，UI 只跑與使用者操作有關的代表案例；完整公式矩陣仍交由可重複工具核對，避免每個候選都重走選單。

## 待建立的遊戲畫面導覽

第一次實際操作時，記錄每一步的「畫面名稱／可見文字或圖示、動作、完成標記、截圖檔名」。優先可存取性節點；canvas 無節點時，以當次截圖定位，不沿用舊截圖絕對座標。目前不填入猜測的快捷鍵或按鈕位置。

| 流程 | 必須取得的 UI 證據 |
| --- | --- |
| 啟動→讀檔→遊戲主畫面 | 正確測試槽、角色／山寨辨識、可操作狀態；非僅到標題畫面 |
| 普通裝備→詳細資料 | 範本、品質、等級、詞條名稱與可見效果；對照單件預覽 |
| 選槽→同槽再次洗練 | 初始選槽資格、唯一槽限制、成本顯示與實扣；重啟後限制仍在 |
| 穿戴→卸下→穿回 | 使用正確裝備格，面板效果移除／加入，無殘留舊效果 |
| 遊戲存檔→退出→新程序讀檔 | 原版 UI 存檔完成、新 PID、同槽新值與效果，原始存檔雜湊未變 |
| 丹藥（任務涉及時） | 道具資格、上限、服用後顯示；與持久增量及小數限制分開記錄 |

原生卸穿有延後動作：驗證工具曾需要等待約 500ms；UI 測試應等畫面完成標記而不是把固定延遲當成功。裝備搬移可能改目前列號而保留 y0 初始背包列號，追蹤範本、詞條與雙向指標，不假設序號保持原值。

## 編輯器確認框與選檔

2026-10-21 使用者截圖顯示 `127.0.0.1:8942` 的「目前有尚未匯出的變更…」確認框。這是編輯器 `load()` 的 JavaScript confirm，不是遊戲或 Codex 權限詢問。舊程式只檢查 `model.changes.size`，即使已匯出仍提示；修正後與離頁判斷一致，只在有修改且 `revision !== exportedRevision` 時提示。

- 已匯出修改仍留在變更清單，供預覽及還原；不因下載而清空。再次修改後重新視為未匯出。下載原檔備份不等於匯出修改。
- 測試重新選檔前先確認下載事件及檔案內容；等檔案名稱與目前值更新，再操作分頁。檔案選擇完成並不代表非同步解析已完成。
- 對自己的可丟棄合成資料，可依當次工具的 dialog API 處理預期確認框；對使用者未保存資料先取消，保留內容。不要預設接受所有 dialog。
- 遇到 filechooser／DOM.setFileInputFiles 逾時，先看確認框與目前檔名。模態框可能阻塞後續命令，不能一律判為工具故障；沒有狀態變化就停止重複點擊。處理確認框後再驗證載入；必要時重設工具連線，勿重啟整個使用者瀏覽器。
- 背景分頁仍可能產生前景的原生確認框。只建立必要測試頁，先匯出或還原合成修改，最後清理自己建立的頁面；不要以移除真正的未匯出保護來減少干擾。

修正的回歸測試為 `tests/ui-export-state.test.cjs`：實際執行 UI 事件處理，涵蓋主介面與預覽匯出後換檔不提示、再修改仍提示、取消保留原檔、備份不解除保護及全部還原後換檔。

## 維護紀錄格式

每次 UI 驗收附版本／來源摘要、環境、初始資料、可見操作、預期與實際結果、截圖路徑、停止／重啟 PID、原始雜湊核對及未完成項目。原始截圖和存檔留 repo 外；repo 只存去識別結果及可重用導覽。首次建立導覽後，後續版本先比對畫面與來源，只有相符才沿用路徑。
