# 任務分派與下一步 prompt

[維護索引](../maintenance.md) · [承接流程](planning.md) · [下一步與目前進度](../research/next-version-plan.md)

使用者以多個 session 推進 SDD：每個 session 跑一段 prompt、指定模型與思考程度，能同時跑的就同時跑。本頁規定 agent 如何把下一批未完成任務拆成 prompt，以及每段結束時怎麼交棒。

## 何時產出分派計畫

- 「下一步做什麼」：回報進度後附上**分派計畫**（下方格式），不開始實作。
- 「繼續實作下一版功能」：先產出分派計畫。第一個可執行 prompt 建議的模型與目前 session 相同時，直接在這裡執行它，完成後照「收尾交棒」交出其餘 prompt；模型不同時只交出計畫，由使用者另開 session。
- 使用者指名某一段（例如「做 A4」）：照該段 prompt 的界線執行；目前模型比建議的弱時，先提醒一次再照做。
- 分派計畫以目前 SDD 任務檔的「分派」表為準；表不存在或過時，先依本頁規則補表並寫回 SDD，再產出 prompt。

## 選模型

暫定 Claude 5.5 系列；遇到新模型時只更新本節。

| 模型 | 適用 | 不交給它 |
| --- | --- | --- |
| **Opus 5.5** | 改 `src/core.js` 的資格、交易、回滾；碰到或需要避開共用樞紐的設計；證明閘門、首次證明合併；原生結果判讀與規格修正；跨模組設計與新研究 | 純機械性的勾選與文件同步（浪費） |
| **Sonnet 5.5** | 有既有範本可照做的程式：規則資料模組、獨立 oracle、manifest／分片、proof 接線、測試、沿用既有樣式的介面；照手冊跑原生分片與選跑並處理一般失敗 | 新的 core 交易設計、證明合併、原生反證判讀 |
| **Haiku 5.5** | 純文件同步、勾選與執行紀錄、連結修正；照固定指令跑檢查並整理結果；平行分支的整合推送（無衝突或只有紀錄行衝突） | 任何 `src/` 或 `scripts/` 的邏輯修改 |

範本判準：同類工作在已歸檔 SDD（例如 `sdd/archive/2026-10-23-treasure-level/`）有完成的對應任務，就算「有範本」。

## 思考程度

預設「中」，prompt 一律寫明。只有下列情況建議調整，並在 prompt 標頭註明原因：

- **高**：core 交易／回滾與精確 token、證明合併與閘門、原生結果與規格衝突的判讀、新研究結論。
- **低**：Haiku 的文件同步與勾選、只跑固定指令並回報。

## 依賴與並行

- **必須依序**：後一段讀前一段的產出（資料 → 資格 → 預覽 → 交易）；同一份程式檔（`src/core.js`、`knowledge/catalog.json`、`knowledge/verification.json`、`index.html`／`sw.js`）只能一段一段改。
- **原生遊戲一次一段**：並行副本尚未實作，同時只能有一個 session 啟動隔離遊戲。
- **可並行**：只新增或修改互不重疊的檔案（例如獨立 oracle、manifest 腳本與其測試），且不需要對方的產出。
- **並行 session 的做法**：各自在新 worktree 分支工作；SDD 只改自己的任務行與執行紀錄，不改進度入口；推送前 `git pull --rebase`，紀錄行衝突時兩邊都保留。同一組最後完成的 session（或另開的 Haiku 整合段）負責更新進度入口的「下一步」。
- **建置**：只有改到 `src/` 或 catalog 的段落才重建 `index.html`／`sw.js`；並行段落不改這兩個檔。

## 分派計畫格式

先一張表，再逐段給完整 prompt。

| 段 | 任務 | 模型 | 思考 | 前置 | 可同時跑 |
| --- | --- | --- | --- | --- | --- |
| 1 | A4 | Opus 5.5 | 中 | A3 已推送 | 2、3 |

每段 prompt 開頭四行固定：

```text
模型：Opus 5.5｜思考程度：中（預設）
位置：主 checkout（或：新 worktree 分支，結束 rebase 後推送）
前置：A3 已勾選並推送到 main；未滿足就停下回報
可同時跑：段 2、3（不同檔案）
```

接著寫：要做的任務與 SDD 連結、只讀哪些文件、界線（不改哪些檔、旗標與證明）、驗證（測試、`node scripts/core-slice-report.cjs` 的預期結果）、收尾（照 `docs/maintenance/release.md` 最短流程）、回報格式（下一節）。

## 收尾交棒

每個 session 結束時，回報除了結果，一定要附「下一步」：

1. 做了什麼、提交 SHA、推送與否、測試及切片報告結果。
2. **下一步 prompt**：依 SDD 分派表，列出現在已解鎖、可以開跑的每一段完整 prompt（含四行標頭）；同時解鎖多段就標明哪些可並行。
3. 仍在等待的段落與它們在等什麼（例如「A9 等 A7、A8 都推送」）。
4. 需要使用者決定或授權的事項（例如原版 UI、發布）；沒有就寫「無」。
5. 原生結果推翻規格、或切片報告顯示意外重證時，下一步改為給 Opus 的修正 prompt，不照原計畫往下排。

最後一段完成時，下一步改為：下一階段的分派計畫，或功能收尾與候選選擇。
