# V1.0.10.2 相容性調查與遊戲讀寫驗證

調查日期：2026-10-21。分析使用者本機 Steam 正式版 `package.nw`，Steam App ID 4267800、build **26094666**，對照 repo 既有 V1.0.9.1 的 catalog、驗證指紋與研究公式。先完成事件與 expression factory 靜態核對，再以隔離副本執行真實遊戲載入、存檔及程序重啟驗證；解包資料、完整分析、玩家資料與原始測試紀錄均放在 repo 外。

結論：已核對的資源、材料、名稱及經驗座標沒有發現搬移，三類升級需求公式與職業樹保持一致；產出計算、速度上限及部分 UI 事件已有變更。名稱與三類經驗已通過 Windows 新版的遊戲載入、原版存檔與重啟讀回。`knowledge/catalog.json`、`knowledge/verification.json` 與單檔 HTML 已同步 V1.0.10.2，全部 13 個來源指紋一致；新版 macOS 啟動器不在此次驗證範圍。

## 產出與速度變更

- `采集量计算` SID `776958833983098` 以 expression `5543` 計算 **(100 + 屬性 #72) / 100** 的獨立倍率。採集／製作／發展的回傳分支 expressions `5546`–`5548` 均納入該倍率；額外固定產出 #65／#66／#67 則在最後加上。
- `属性计算` 的攻擊間隔分支，事件 SID `759979764842732`、expression `5326`，將結果限制為至少 **0.2 秒**。
- 同函式的工作間隔分支，事件 SID `979643493291280`、expression `5331`，同樣至少 **0.2 秒**。
- 技能冷卻屬性分支，事件 SID `593181694409238`、expression `5340`，限制為 **0–70**；`技能冷却时间` 的事件 SID `322188173699759`、expression `5466` 也將冷卻減免限制為 **0–70%**。

修改器目前唯讀顯示衍生屬性，增加的是直接獲得的最終經驗，不重算工作產量或效率。因此此次分析沒有理由直接改寫這些欄位或放寬編輯權限。新版名稱索引與繁中對照已同步將 #72 改為「最終增產」。

## 重跑與後續驗收

將自己的新版遊戲選定來源解包至 repo 外後：

```sh
node scripts/extract-game.cjs --source /outside/repo/unpacked-game --audit-only --audit /outside/repo/audit.json
```

`--audit-only` 可分析未知指紋，輸出來源指紋、統計、函式、動作與讀取索引；不呼叫 catalog 產生器，也不修改名稱對照表或開放寫入。一般重建仍會拒絕未知事件／runtime。原始 audit 必須位於 repo 外。

本輪以此入口解析實際新版來源；合成測試另確認未知來源只分析、原有重建閘門仍生效、跨版本事件／runtime 組合遭拒，以及 repo 內的原始輸出被拒絕。完整核心測試與建置同步檢查通過。

`verify-game.cjs` 現支援 Windows 與 macOS。Windows 重跑準備範例（各路徑替換為自己的來源，輸出目錄須已存在且位於 repo 外）：

```powershell
node scripts/verify-game.cjs --setup --source 'D:/audit/unpacked-game' --runtime 'D:/SteamLibrary/steamapps/common/塔防山贼模拟器/game.exe' --save-file 'D:/SteamLibrary/steamapps/common/塔防山贼模拟器/save/ea2save.dat' --catalog 'D:/audit/candidate/catalog.json' --artifacts 'D:/audit'
```

使用輸出的 state 路徑依序執行 `--probe`、`--load --mode 备份`、`--save`、`--assert`、`--stop`、`--restart`、`--probe`、`--load --mode 存档`、`--assert`、`--stop`；每一步等待前一操作完成，`--probe` 確認布局已就緒。完整驗證閘門流程見[維護指引](../maintenance/core.md#重建知識與開放寫入)。Windows 手動存檔正常位於 `save/` 子目錄；歷史 Mac 路徑差異仍見存檔知識筆記。
