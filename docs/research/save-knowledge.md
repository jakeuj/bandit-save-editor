## 可重跑解析

```sh
node scripts/extract-game.cjs --source /path/to/unpacked/game --audit /tmp/bandit-audit.json
node scripts/build-editor.cjs
node --test tests/*.test.cjs
```

解析器確認 `project[3][12]` 為 save，使用 `C3_GetObjectRefTable` 辨識 Array 操作，對照 `project[6]` 事件 SID 與 `C3_ExpressionFuncs`。只在空白且限時的 VM 建立 expression factory 陣列，並不啟動遊戲或執行這些 factory。讀取參照與完整解析輸出僅在 repo 外的 audit；提交的是欄位寫入位置索引、必要名稱及規則摘要。

目前 V1.0.11.2 辨識 725 個事件函式、863 個存檔陣列動作，其中 850 個 SetXYZ，及 2,825 個 save.At 讀取參照。名稱索引共 1,762 筆，涵蓋材料、角色範本、職業、屬性、物品、科技、建築、任務、天賦、設施及靈物。名稱採遊戲文字；未提供繁體的名稱用 macOS Foundation Hans-Hant 轉換或人工補充，轉換表保存在 `knowledge/traditional-names.json`，其他平台可重用。

事件／runtime 指紋未知時，解析器停止產生可編輯知識；其他資料表指紋改變時，重建不保留原本的新增可寫旗標。需重新查核座標、公式與來源；完整指紋相同才保留既有旗標。驗證紀錄另由建置工具核對全部 15 個來源檔案。單檔 HTML 內嵌知識與程式，使用者下載後不必持有或上傳遊戲資料表。

## 名稱與型別

- 山寨名：`[1,1,0]`，初始化事件 SID `267734447925333`。
- 角色名：`[r,1,2]`，改名寫入 SID `342994246102946`。
- 繁／簡中介面均要求 1–6 個 JS UTF-16 code units，禁止 ASCII 空格；其他語言 1–16。本工具採繁中規則，另拒絕控制字元作為編輯器限制。Emoji 通常占兩個單位。
- 字串輸出以 JSON 字串 token 轉義；數值與字串型別須與原欄位一致。未修改區域完全保留原始文字、BOM、大型整數、空白及指數寫法。
- 已知唯讀欄位透過舊 `set`／自訂座標也不能繞過規則；未辨識的數值座標保留既有手動整數編輯。未知資訊不會在圖鑑偽裝成已驗證欄位。

## 成長規則

這裡增加的是「直接獲得的最終經驗」，不扣取得成本、共用經驗或操練點，也不模擬工作效率加成。遊戲原自然經驗函式每次最多升一級；修改器將相同公式逐級批次結算，抵達上限即將餘額正規化為零。

### 角色

- 等級 `[r,3,2]`，自然經驗餘額 `[r,4,2]`。
- 上限 `(floor(save[r,50,2]) + 1) × 30`，函式 SID `669796499635515`。
- 升級需求 `round(round(2000 × L^1.4 + 10000 × 1.057^L − 11570) / 1000) × 1000`，函式 SID `361916000013616`，expression `5421`。
- 自然獲得經驗 SID `220487631902723`。`[r,56,2]` 是共用池投入／退款基數，不是自然獲得的總經驗；這條操作不改它，也不改共用池 `[2,2,0]`。

### 職業

- 等級 `[r,job,4]`，餘額 `[r,job,5]`；零級表示未習得，第一版不藉經驗解鎖。
- 上限 `min(30, floor(save[job,5,0]))`。30 是當前版本全局職業等級上限；另一值是山寨操練上限。
- 職業等階 `T` 取 `zy[job,3]`。需求為 `round((2500 + 500 × L) × T² × 1.2^(T−1) / 500)`，T=2、3 乘 250，其餘乘 500；函式 SID `792203991116851`、expressions `5422`／`5423`。
- 自然事件 SID `437350704174070`。新增量可有一位小數；先 floor 原餘額再加，升級扣除時再 floor，符合本體捨去舊小數的行為。
- 自動轉職 `[r,59,2]>0` 時，本工具拒絕增加職業經驗，請先在遊戲中關閉；不修改職業 ID 或代做轉職。

### 職業轉職圖鑑

2026-10-21 對照使用者提供的 [piplord 社群指南](https://steamcommunity.com/sharedfiles/filedetails/?id=3822759356)附圖與本機 V1.0.9.1 資料。原圖僅涵蓋第一至第五階；遊戲 `zy.json` 另有第六階，因此公開圖鑑涵蓋 47 個職業、六個等階（1／2／4／8／16／16 筆）、16 條流民至第六階的完整路線。

- `zy[id,3]` 為等階，`zy[id,4]` 為系別（1 力量、2 敏捷、3 法術、4 生產）。附圖以 STR／AGI／INT 表示資質方向，圖鑑將法術系標示為「法術系（智力）」。流民、嘍囉與村民的遊戲系別值仍為 1，路線表以中性色呈現共用起點。
- `zy[id,10]`、`zy[id,11]`、`zy[id,12]` 為前置職業 ID。此版本只有第 10 欄非零，每個非起始職業只有一個前置職業；第六階依序接在第五階的 16 個職業之後，並非依英文名稱猜測。
- `转职条件判断` SID `703456569753928` 檢查三組前置職業等級，以及目標職業的 `save[id,5,0] > 0`。`转职等级要求` SID `793060806711494` 對前置 ID 1（流民）回傳 5，其餘回傳 10。此處要求的是**前置職業等級**，不是角色等級，也不是工作技藝等級。
- 對應 expressions `2166`／`2168`／`2170` 讀取角色前置職業的第 4 層等級；`2167`／`2169`／`2171` 呼叫等級門檻函式；`2172` 讀取目標職業第 0 層第 5 欄。來源指紋沿用 catalog 的 `data.json`、`scripts/c3runtime.js` 及 `zy.json`。
- 工作標籤依附圖整理為「指南建議工作」。實線有標工作、虛線未附說明，不能因此推定隱藏條件或禁止工作。第六階的工作沒有原圖證據，標示未涵蓋，不自行沿用第五階作為已驗證事實。

資料表關係由解析器重建；社群來源、工作摘要與已核對門檻由 `knowledge/profession-guide.json` 維護，建置時一同內嵌。頁面查閱、角色前置等級及操練解鎖對照均不修改存檔，也不開放直接寫入職業 ID。此輪為程式證據與瀏覽器唯讀驗收，未增加隔離遊戲轉職實測或擴大可寫群組；既有經驗寫入驗證維持原範圍。

### 九項技藝

1–9 分別為伐木、採礦、種植、鍛造、工藝、煉丹、建造、研究、操練。

- 上限 `[r,21+k,2]`，等級 `[r,30+k,2]`，經驗 `[r,39+k,2]`。
- 升級需求 `round(round(10000 × 1.05^(L−1) + 500 × (L−1)) / 500) × 500`，函式 SID `879380531434698`、expression `5424`。
- 自然經驗函式 SID `890068128550912`，狀態更新 SID `727573628418621`、`927397704806210`、`275143275632288`。
- 既有經驗操作讀取個別存檔上限，不固定為100。v2.8的一般隨機角色範圍另受六品質招募公式限制，Q6主要技藝最高88；不能把其他角色的上限範圍套入本案。不存在第10項技藝，該索引會碰到第一項經驗欄位。

`刷新单角色全属性` SID `202028565292461` 把升級後數值寫入暫存物件，而不是 save；遊戲載入後自行計算。編輯器保留其他持久資料。

v2.8具名操作以九項為一組，僅支援已招募、範本0、非在監、無結丹／重生階段紀錄的一般角色。固定目前品質、原始資質與三槽天賦，枚舉共同招募傾向及不同主副技藝位置；各欄單獨落在範圍內不足以通過。C<L阻擋，下調至C=L且E>0也阻擋；提高C只改真正變更的上限token，L/E保留、不立即升級。第一次有效變更把該角色既有與後續的單項／九項批次技藝經驗納入27欄累計還原；undo仍按每筆交易，其他角色維持原分組。自訂座標不能繞過具名操作。

## 驗證及限制

新增可寫群組由 `catalog.verification` 控制。測試程式可在自己的 VM 開啟閘門驗證核心；公開 HTML 的閘門只在隔離遊戲完成載入、遊戲存檔與重啟後才開啟。實測結果另見本節後續紀錄。

`scripts/verify-game.cjs` 使用獨立 app、遊戲、profile、存檔與 Steam 寫入鏡像；保留原生 Steam 初始化及身分，不對正式 Cloud、成就或統計進行寫入。測試程序僅以自己的 PID 停止，並比對來源存檔雜湊。需要 Node 22 以上。

測試在讀入實際遊戲主畫面後暫停模擬時間，避免工作自動取得經驗污染比對；原版函式仍負責存檔。這不是長時間遊玩或真實雲端同步測試。

### 2026-10-20 隔離遊戲結果

NW.js SDK 0.82.0 osx-arm64、Apple M4 Max、macOS 27.0.1。隔離 app 使用不同 bundle ID，遊戲、存檔、Chromium profile 與 Steam 寫入鏡像均在 repo 外；原版授權初始化保留。正式遊戲程序未停止或操作。

1. 使用修改器核心處理測試基準：山寨／角色改名；角色增加 6,500；職業先增加 6,500 再增加 1.5；技藝增加 21,500。
2. 呼叫真實 `读取进度` 事件，由遊戲檔案 IO、初始化及切換布局載入；讀取運作中引擎的 save Array，確認兩個名稱及三組等級／餘額，並確認共用池與退款基數維持原值。
3. 呼叫真實 `存档` 事件寫入手動存檔，解析遊戲產生的檔案，對照相同 10 個欄位。
4. 結束該測試程序，重新啟動相同隔離 app／profile，由 `存档` 模式再次讀回；角色為 Lv 3／500、職業 Lv 3／1.5、技藝 Lv 3／500。三輪均與預期相符。
5. 核對來源存檔 SHA-256 未變；解除短暫暫停後，另確認實際山寨主畫面顯示測試名稱。

### 核心介面與瀏覽器驗收

`FieldDescriptor` 包含座標、名稱、分類、實體、型別、用途、關聯座標、來源 SID、驗證狀態及直接編輯權限。`SaveCore.resolveField(model, coord)` 回傳定義；`setField` 統一限制，`addExperience(model, {kind, characterId, id, amount})` 處理角色／職業／技藝的連動。等級及餘額不允許單獨寫入；舊 `set` 及自訂欄位設定格式保留。`transaction` 共用一筆歷史，錯誤全部回滾。

連續增加同一個角色的同一項經驗後，「還原」會將那一組累計修改回到載入時的基準，避免只還原餘額卻留下等級；「復原一步」回到上次交易。其他角色、職業及技藝不受該組還原影響。

- 12 項 Node 合成測試通過：精確 token 輸出、大型整數、BOM、名稱轉義／型別、經驗公式、跨級、上限、未習得職業、自動轉職、驗證閘門、回滾與整組復原。
- 2501 × 60 × 22 的合成存檔完成載入、實體搜尋、編輯與比對；表格每頁最多 50 筆，未將整份陣列渲染成 DOM。
- 桌面瀏覽器完成選檔、角色／職業／技藝增加、改名、預覽、還原、復原一步、下載與重新比對。390px 手機版完成增加、預覽與下載，沒有頁面水平溢位。
- 實際下載的桌面及手機修改檔，與核心指定 token 輸出逐字一致；重新載入正確辨識三個差異欄位。
- 離線相依性檢查通過：所有執行程式及知識內嵌，沒有外部 script／stylesheet 或網路 API，CSP 禁止連線。內建瀏覽器阻擋 `file://`，因此本輪未自動驗證直接雙擊離線 HTML 的完整 UI 流程；需以一般 Chrome／Edge 開檔確認。

### Mac 存檔位置補充

V1.0.9.1 的 `savedir/eaNsave.dat` 是「雲存檔」下載快取，`backup/eaNsave.dat` 為自動備份。手動「讀檔」使用 `save\\eaNsave.dat`；目前 Mac 準備工具未正規化這一組路徑，因此在 `game/` 下產生**檔名包含反斜線**的 `save\ea1save.dat` 等檔案，而非 `save/` 子目錄。本輪已實際寫入並在重啟後讀回此路徑；沒有修改正式啟動器。修改存檔須放回取出時的同一位置，並選對應讀檔分頁。
