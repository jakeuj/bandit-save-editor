# 第二批：裝備品質、詞條與丹藥資質增量研究

研究日期：2026-10-21。基準 **V1.0.10.2／Steam build 26094666**，承接 [v2.1 研究](advanced-editing.md)。初次交付只有靜態研究與驗證規劃；其後使用者要求實作係數與丹藥增量，最新結果見文末「v2.2 實作與隔離驗證」。以下「建議」不是遊戲已驗證行為，也不將 v2.1 的等級實測當成品質、詞條或丹藥的證明。

## 結論與建議順序

| 項目 | 可行範圍候選 | 修改限制與優先順序 |
| --- | --- | --- |
| 既有詞條係數 | 保留合法詞條 ID，只調整既有槽係數；原版含兩位小數 | 最小候選，先做。限普通裝備、原版品質對應係數區間，不新增槽、不重置洗練旗標 |
| 丹藥資質增量 | 只改有效角色的力量／敏捷／智力丹藥增量 | 次優先；先限無結丹引用、能完整算出資質來源的角色。單位、角色上限與丹藥上限須分開；支援歸零／下降候選 |
| 裝備品質 | 品質 1–6 的既有普通裝備；與詞條結構一併審查 | 不是獨立的一欄修改。升品缺少新槽時，須另設明確的交易方案；降品遇多餘詞條或等級超出新上限先阻擋 |
| 替換詞條 ID | 限原版對應物品可抽到的屬性集合 | 後於係數調整；ID、係數、洗練槽限制及屬性刷新需一起驗證，不提供任意屬性清單 |
| 超限品質／第六槽／超限係數／超限丹藥 | 尚無實測或完整生命週期證明 | 不列入首輪公開範圍；即使有限數值也不能視為安全 |

這是縮小實作風險的建議順序，不表示已批准實作。寶物、內丹、套裝、飛升情境、實體生成、移動歸屬及重置洗練限制均另案；不以「裝備」大類直接判定可寫。

## 一、裝備品質與生命週期

以一般裝備實體 `i`、所在庫 `z` 表示：背包是 z7、穿戴庫是 z9。v2.1 的有效實體／範本／雙向穿戴指標檢查應沿用；如果第二批新增背包 z7 寫入，需獨立納入驗證，不能用 z9 的證明代替。

| 欄位 | 原版證據與意義 |
| --- | --- |
| `[i,5,z]` | 當前品質 Q；`物品品质文本` SID `589712995086958` 有 1–6 六分支：凡物、優秀、精緻、絕世、傳說、神話 |
| `[i,6,z]` | 等級 L；上限 `10+(Q−1)×5`，沿用 v2.1 的 SID `713681756866045`／expression `5315` |
| `[i,9..14,z]` | 六個實體槽位的詞條 ID；有欄位不表示六個均為原版可用槽 |
| `[i,15..20,z]` | 對應六槽係數，單位是原公式使用的百分比係數，不是直接屬性數值 |
| `[i,23,z]` | 取得普通裝備時會寫入取得品質，但**不是所有物品都可稱為原始品質**；套裝合成另有語意 |
| `[i,28..33,z]` | 各槽是否已洗練的標記；原版寫 1、以 `>=1` 計數，不是總洗練次數 |

`获得物品` SID `601593514747018` 的普通分支 `166680919655131` 同時將 Q 寫入 y5 與 y23，生成詞條的子事件 `491911663973794` 寫入 ID 與係數。`装备库存入` SID `791657421740250`／子事件 `959041203712077`、`装备库取出` SID `654692930556623`／子事件 `418018161514165` 逐欄搬移。修改後必須驗證卸下、穿回後所有相關欄位都保留，而非只測載入畫面。

`套装合成` 子事件 `835824606167319` 將 y23 改成靈物 `[靈物序號,4,18]`（expression `3563`），y26 取靈物 y10（`3564`），y27 記錄原物品資訊；`套装数量检测` 的多個子事件（例如 `462000374088658`）透過 expression `3028` 讀取穿戴裝備 y23。故不能將 y23 一律與 y5 同步，否則可能改變套裝識別／計數。初版建議排除 `wp[template,4]="套装"`，保留所有 y23／26／27 原值，品質升降前另外確認普通物品 y23 的圖示及後續轉換語意。

**品質操作的未決點：**原版 `装备词条数量` 回傳 `clamp(Q,1,6)−1`（SID `910195347276964`，expression `5282`），Q1–Q6 分別為 0–5 槽。升品會增加原版應有槽數，但直接改 y5 不會重跑取得物品生成；降品可能留下隱藏但仍被某些計算分支讀到的欄位。建議以完整預覽的原子交易處理品質與明確指定的新詞條，或暫不開放這種升品；禁止偷偷隨機補槽、清除舊槽或降低等級。品質下降時，L 超過新上限、已有槽超出新數量、係數不在新區間、洗練旗標落於被移除槽，任一成立即阻擋，直到對應交易設計及實測完成。

## 二、詞條 ID、係數與洗練限制

### 原版合法池

`装备随机词条编号` SID `557896778643212` 枚舉 `sx` 列，先要求 `sx[id,8]=1`，再依 `wp[template,23]` 過濾：

- 物品類型「战斗」：`sx[id,13]` 為「战斗」或「通用」。
- 物品類型「生产」：`sx[id,13]` 為「生产」或「通用」。
- 物品類型「通用」：還排除 `sx[id,13+wp[template,9]−39]=1` 的屬性（expression `5285`）。這是動態欄位檢查，不能只保留「通用」文字的詞條。

本版 `sx[,8]=1` 共 38 個候選屬性，但這是過濾前集合，**不能把這 38 項都開給每件裝備**。例如暴擊幾率 ID12、等級經驗 ID36、技藝經驗 ID37、最終增產 ID72 分屬不同類型。原隨機函式未帶入目前其他槽的 ID，也未在該函式內檢查重複；這是局部靜態觀察，不能據此宣稱任意重複詞條都已通過遊戲驗證。第一版替換 ID 可保守拒絕新增重複，既有重複則保留並單獨評估。

### 係數不是正整數

`装备词条系数` SID `631300007252337`、expressions `5287`–`5289`：

`下界=10×(Q−1)`，`上界=60+10×Q`，`係數=round(random(下界,上界)×100)/100`。

| 品質 Q | 原版隨機係數外包區間 | 原版槽數 |
| --- | --- | --- |
| 1 | 0–70（但一般裝備無詞條槽） | 0 |
| 2 | 10–80 | 1 |
| 3 | 20–90 | 2 |
| 4 | 30–100 | 3 |
| 5 | 40–110 | 4 |
| 6 | 50–120 | 5 |

這是由公式得到的邊界，不保證亂數端點生成機率；四捨五入後的上下界值需原生驗證。建議輸入以百分之一為步進，在十進位縮放後檢查安全整數，拒絕 NaN、Infinity、過多小數及區間外值。不能套用 v2.1「所有值皆正安全整數」的前提，也不能把係數 100 說成必然屬性 +100%。

實際效果進入 `装备属性计算` SID `131416746119248`，expressions `5356`／`5358` 再呼叫 `装备主属性` SID `773239288013696`；不同屬性用不同分支與向下取整。例如暴擊類 expression `5299` 為 `floor((2+0.75T+0.01L)×(係數/100)×100)/100`；暴傷類 `5300` 為 `floor((8+3T+0.4L)×(係數/100)×100)/100`。因此係數改了而面板未變，可能是取整，也可能刷新缺漏，須同時觀察原生函式結果與完整角色屬性。

### 洗練是槽鎖定，不是使用總次數

`词条洗练` SID `619743323262026` 的寫入子事件 `564254928232839` 改該槽 ID、係數，再將 `[i,27+槽號,z]=1`。`装备已洗词条数` SID `316241056309469`、expressions `4862`–`4867` 逐一檢查 y28–33，對 `>=1` 的槽加一；重複洗同一槽不增加此計數。

`刷新词条洗练页面` SID `780562691790658`：子事件 `196601779910507` 在尚未選過洗練槽時提供選擇；其 else 分支透過 `775039415186059` 檢查該槽旗標，停用未選過槽。提示 expressions `4847`／`4848` 明示未飛升裝備只能洗一槽、選後不能改其他槽。**函式與 UI 不完全同等防護**：`词条洗练` 本體檢查正槽號／正實體號、庫別 z7 或 z9、魂魄足夠，但本輪在函式本體未見再次執行「只可選一槽」或「槽號不得超過品質槽數」檢查。不能因直接呼叫可寫便將它當成原版允許；編輯器需要自行實施 UI 層限制。

最小候選「只調既有係數」保留 ID、所有洗練旗標與選定槽。為避免暗中解鎖多槽，普通模式建議只允許已選定的洗練槽；若尚無選定槽，要另設明確、預覽可見的「選定一槽」操作，並驗證旗標交易。若產品希望不受此限制，應標成另一個修改語意及獨立驗證項，不冒稱原版洗練。替換 ID 同樣遵守合法池與同一槽鎖定，禁止清零旗標來規避限制。

## 三、丹藥資質增量

### 欄位、單位與實際上限

`[r,13,2]`／`[r,14,2]`／`[r,15,2]` 分別為力量／敏捷／智力丹藥增量 B。`角色资质计算` SID `876351181502276`、expressions `5425`–`5427` 計算 `round(100×(A+B/10))/100`。原始增量 1 對應顯示資質 +0.1；它不是丹藥顆數，也不是角色基礎資質。

A 是 `属性计算(r,104..106)`，SID `211049884056972`／expression `5338`：`baseRaw/10 + 天賦 + 內丹 + 裝備`。其中 `baseRaw` 為 y10–12，不能直接使用角色範本取代完整 A。正常載入另有範本回填，參見第一批研究；新增操作不可寫 y10–12。

`角色资质上限` SID `110565347746026`、expressions `2232`–`2234` 回傳 `C=round(100×A×M)/100`。`角色资质上限倍率` SID `358500068340403`、expressions `4049`–`4051` 使用：

`M=1.5+Σ save[save[r,2k,16],15,17]`，`k=1..int(save[r,50,2])`。

因此不能把所有角色上限寫死成基礎資質 ×1.5。涉及 z16 結丹紀錄、z17 內丹引用的角色必須先核對引用合法性及相關資料；最小候選建議只處理無此引用且完整 A 可重建的角色，高境界列未開放原因。

`丹药资质上限` SID `159597372843995`／expression `2236`：`P=yx[cl[材料,2],cl[材料,6]]`，分別用階、品質索引；例如一階品質1為10、品質6為40，九階品質6為1000。這些是總資質上限，不是可直接填入 B 的數字。`普通丹药效果` SID `329375418336385`／expression `2238`：每顆 `E=round(階^1.2×2^(品質−1))/10`。

### 服藥的前置判斷與雙重 clamp

`服用普通丹药` SID `660833363431874` 先要求 `cl[,5]="丹药"`、材料數量足夠，再依 `cl[,3]` 的力量丹／敏捷丹／智力丹分支，要求目前顯示資質同時小於 P 及 C。寫入子事件 `880300005151299`／`669100206862089`／`405296456902521`、expressions `2255`–`2257` 為：

`Bnew=clamp(clamp(B+10×E×數量,0,10×C−baseRaw),0,10×(P−A))`。

**內層使用 `baseRaw`，外層使用完整 A**，兩者不能在公式記錄中互換。當天賦／內丹／裝備有額外 A 時，單純將 B 上限宣稱為 `(C−A)×10` 不是原版寫入的逐字等價式；但編輯器可以採更保守的顯示上限，必須標示為產品限制，並測試下一次原生服藥如何處理。下界負值、C/P 低於當前 A、邊界小數及多顆溢出結果均須拒絕或待驗證，不能默默套 clamp 修正使用者存檔。

建議區分兩種可能設計，實作前選定：

1. **直接指定累積增量**：不消耗材料，普通模式要求顯示結果不超 C，並明示採用哪種丹藥 P 作為來源上限；不能憑空選最高九階藥就宣稱角色目前可取得。先用非負安全整數 B（0.1點步進）涵蓋常見生成值，原生 clamp 留下的小數原樣保留並標示尚未可編輯。
2. **模擬指定丹藥效果**：選擇有效材料 ID／顆數，完整重現前置判斷與雙 clamp，但取得成本豁免。預覽需顯示原始 B、顯示總資質、兩個上限及實際新值；這是不同 API 語意，不能與「直接指定」混用。

兩者都不改材料數量、基礎資質、天賦、內丹及衍生屬性。下調／歸零的候選必須驗證其對角色面板、工作／戰鬥及後續服藥的影響，不因減少數值就免測。

### 載入、招募與重生

靜態寫入索引顯示這三欄由服用普通丹藥寫入；招募／收監等角色建立流程初始化為0。`角色重生` SID `360229107749216` 的子事件 `659056119211235` 明確將三欄清零。不能將本功能稱為「永久資質」；驗收時重生後清零是預期結果，不是資料遺失 bug。靜態索引未發現一般載入將這三欄依角色範本覆寫，但仍須真實載入、原生存檔及停止後重啟證明持久性。

## 四、原研究驗證計畫（執行結果見文末）

所有案例使用 repo 外隔離副本及真實存檔副本，保留 Steam 原生初始化；不套用正式安裝補丁。開始與結束核對原始存檔 SHA-256，驗證來源與 candidate catalog 的完整指紋集合，包括實際採用的新表。每組記錄來源、實體分類、前後原始欄位、原生函式值、畫面及失敗原因；原始玩家資料不提交。

固定流程為：修改副本 → 真實遊戲載入 → 原生存檔 → 停止程序 → 重啟讀回 → 行為驗證 → 再次存檔／停止／重啟。單純呼叫函式或儲存值未變不足以開閘門。

| 群組 | 必測案例與邊界 | 行為及成功條件 |
| --- | --- | --- |
| 係數一般 | Q2–Q6；各品質下界／上界／兩位小數；原值升降；背包／穿戴；已有槽／空槽／錯互指 | 精確持久；主屬性不意外改變；指定副屬性符合原生計算及取整；卸下穿回；原生再洗同槽可正常運作 |
| 詞條 ID | 通用／戰鬥／生產池各代表；wp9 動態排除；無效ID、非隨機屬性、重複、錯類型、超出槽數 | 合法項實際作用；原 ID 效果消失、新 ID 效果出現；檢查完整刷新避免殘留；違規項交易前拒絕 |
| 洗練旗標 | 未洗、單一已洗槽、異常多槽旗標、空槽有旗標 | 不重置歷史；不暗中開放其他槽；原生 UI 鎖定與後續成本一致；異常結構保持停用 |
| 品質一般 | Q1↔Q2、Q5↔Q6；缺槽升品、滿槽降品；L等於／超過新cap；係數超出新區間 | 先驗證阻擋策略；若後續實作聯動交易，逐欄預覽與復原；圖示、提示、詞條數、升級上限一致；套裝及飛升保持排除 |
