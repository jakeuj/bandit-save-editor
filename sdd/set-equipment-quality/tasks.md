## 驗收條件

- 情境：合法背包或 z9 套裝升品，保留槽 roll 隨 Q 平移，使用者明選新增 P原 尾槽；y6、y23／26／27、歸屬及其他欄位保持，新槽旗標為 0。
- 情境：降品刪尾槽須確認；會移除已選槽或超過新 cap 時拒絕且檔案／歷史不變。先合法降等級再降品質可成功，不暗中代降。
- 情境：原生洗練使唯一已選槽變成 P套 專有 ID 後，品質及等級都接受已證明範圍；同 ID 出現在未選槽則拒絕，不把聯集擴及全部槽。
- 情境：原生洗練後新效果正確、舊效果確實移除；單件品質效果改變而品質交易本身不改 S／N／部位數及額外套裝加成。原生穿卸後另依組合重算。
- 情境：z7／z9 同列號互不影響，y0 與當前列不同仍按有效來源識別；搬移以真實目的列核對，y0–49 與 y50–59 分別監看，穿戴指標唯一且雙向一致。
- 情境：四個庫別／方向證明獨立；只證明 z9 升品不能開 z7 或降品。缺來源、完整矩陣、IO／重啟或必要 UI 時仍關閉，普通品質與代表遷移不能補過。
- 情境：19,440 基礎案、864 套裝組合及額外維度均有固定 manifest 與實際結果；未知、失敗、抽樣未命中與不存在組合分列，不假稱自然六件效果已驗證。
- 情境：品質、等級交錯修改能逐步 undo 或整件累計還原；精確匯出保留未修改原文，兩庫同列號不互相還原，失敗不留下部分交易。
- 情境：基準源自相符版本原生取得／合成與洗練，玩家原檔及快取雜湊不變；舊等級基準只作輸入，不計為品質已通過。
- 情境：最終核心變動後，套裝等級擴張範圍與技藝上限等相依證明有效，建置不靠關閉既有功能通過；交付區分合成、原生公式、IO、UI 與發布。
