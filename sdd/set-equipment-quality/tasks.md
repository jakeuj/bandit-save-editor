以下工程工作以重用現有模組、每項 30–60 分鐘為目標；完整自動矩陣另外分片執行並記錄耗時，未全部完成不能勾選。開工前若仍有超過一小時的工程項目，先拆 A／B 子 SDD，每份至多十條；不把規模估計當實作完成證據。

- [ ] 2. 整理共同套裝資格：按未選槽 P原、唯一已選槽 P原∪P套 驗證，等級及品質使用同一政策；補正反向合成案例與普通裝備回歸。驗收：只有已選槽可接受套裝池專有 ID，等級仍只改 y6，不擴大詞條 API 權限；原生有效性留 B 補證。
- [ ] 3. 建立候選品質交易與預覽：重用普通品質模式，實作四群組分派、roll 平移、新尾槽明選、刪槽確認、cap／已選槽阻擋與整件還原。驗收：精確 token、無變更、失敗回滾及品質→等級→品質 undo 合成測試通過；正式群組未開放。
- [ ] 4. 建立獨立 oracle：重用已核對公式模組但不讀被測預覽；分開交易、生成可達性、單件／套裝效果與生命週期預期。驗收：涵蓋攻擊 L×Q、取整、舊效果移除、S／N、搬移 50 欄與尾十欄監看，原生升品不存在的界線明確。
- [ ] 5. 固定首次 manifest 與 proof 接線：列 19,440 基礎品質、至少 864 組合效果及額外邊界／雙池／拒絕／等級回歸，按四群組拆分；接 requirements、suite、遷移相依與摘要綁定。驗收：合成分片可對帳，漏案、重複、錯方向、過期 checkpoint、缺 IO／UI 或只有代表遷移均不能首次開閘。

- [ ] 7. 完成品質介面與對應瀏覽器案例：庫別／方向狀態、雙池候選、增刪槽／效果預覽、確認重設與阻擋原因，覆蓋桌面／390px、實際下載／重載、file、PWA 離線／交接。驗收：只有有證明的方向可套用，既有已洗詞條正確顯示，下載與核心 bytes 相符。
- [ ] 8. 分片執行完整首次矩陣及兩輪 IO／新 PID：核對四群組交易／效果、原生洗練成本及舊效果移除、穿卸／搬移／排序與品質後等級回歸；依明確授權完成代表原版品質／洗練 UI。驗收：各群組全集可對帳、必要 UI 有獨立證據；未知／未授權／失敗留缺口，不減分母、不開該群組。
- [ ] 9. 核對最終 core 的既有群組相依與重驗：補套裝等級兩庫的跨池新範圍原生證明及原池回歸；依維護指引重驗失效的技藝上限及其他受影響群組，保留未受影響證據。驗收：既有功能可用、證據與最終程式相符，不以替換摘要或關閉既有旗標解除建置阻擋。
- [ ] 10. 合併各群組完整首次證明並核對整合：重讀原始結果重算覆蓋，僅開通過方向；同步知識／建置、研究與驗收狀態，跑相關 Node／proof／遷移／瀏覽器檢查及建置同步。驗收：沒有未解的既有功能回歸，首次與代表證明分開保存；回報實測與缺口，版本／提交／推送／發布另待授權。

## 驗收條件

- 情境：合法背包或 z9 套裝升品，保留槽 roll 隨 Q 平移，使用者明選新增 P原 尾槽；y6、y23／26／27、歸屬及其他欄位保持，新槽旗標為 0。
- 情境：降品刪尾槽須確認；會移除已選槽或超過新 cap 時拒絕且檔案／歷史不變。先合法降等級再降品質可成功，不暗中代降。
- 情境：原生洗練使唯一已選槽變成 P套 專有 ID 後，品質及等級都接受已證明範圍；同 ID 出現在未選槽則拒絕，不把聯集擴及全部槽。
- 情境：原生洗練後新效果正確、舊效果確實移除；單件品質效果改變而品質交易本身不改 S／N／部位數及額外套裝加成。原生穿卸後另依組合重算。
- 情境：z7／z9 同列號互不影響，y0 與當前列不同仍按有效來源識別；搬移以真實目的列核對，y0–49 與 y50–59 分別監看，穿戴指標唯一且雙向一致。
- 情境：四個庫別／方向證明獨立；只證明 z9 升品不能開 z7 或降品。缺來源、完整矩陣、IO／重啟或必要 UI 時仍關閉，普通品質與代表遷移不能補過。
- 情境：19,440 基礎案、864 套裝組合及額外維度均有固定 manifest 與實際結果；未知、失敗、抽樣未命中與不存在組合分列，不假稱自然六件效果已驗證。
- 情境：品質、等級交錯修改能逐步 undo 或整件累計還原；精確匯出保留未修改原文，兩庫同列號不互相還原，失敗不留下部分交易。
- 情境：基準源自相符版本原生取得／合成與洗練，玩家原檔及快取雜湊不變；舊等級基準只作輸入，不計為品質已通過。
- 情境：最終核心變動後，套裝等級擴張範圍與技藝上限等相依證明有效，建置不靠關閉既有功能通過；交付區分合成、原生公式、IO、UI 與發布。
