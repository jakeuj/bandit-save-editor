# 套裝品質

需求類型：**新功能**。日期：2026-10-23。狀態：**提案待確認，尚未實作**。

依據：[套裝品質研究](../../docs/research/set-equipment-quality.md)的有條件 go；目前基準 v2.10／遊戲 V1.0.11.2。本文 Q1–Q10 指向該研究的 SID／expression 證據索引，全部為該版本編號。研究只有靜態核對，本案原生品質證明仍為零。任務見 [tasks.md](tasks.md)。本次只建立這兩份文件，不修改 src、catalog、verification，不啟動遊戲；後續實作及測試須依新的明確授權進行。

## 為什麼做

v2.10 已支援既有套裝等級，品質仍被普通裝備資格排除。套裝品質牽涉主係數、槽數、詞條係數與等級上限，不能只改 y5。合成保留原裝備詞條，但之後原生洗練依目前套裝範本取池，現行套裝等級資格只接受原池，可能拒絕合法洗練後裝備（Q1–Q4）。本案要同時封閉品質交易與這條跨功能生命週期。

## 要改什麼

### 範圍與交易

- 支援 z7 背包、z9 未穿戴及穿戴中的既有套裝，限原普通裝備首次合成、Q1–Q6、T1–T9、數量 1、合法等級、完整合成 metadata 與有效歸屬。未知取得方式、特殊狀態、重複合成、超限顯示尚未支援，不直接稱存檔損壞（Q1–Q4、Q8、Q9）。
- 品質差為 ΔQ：y5 設目標，y8 加 `30×ΔQ`，保留槽係數加 `10×ΔQ`；副係數採百分之一整數運算。主係數須在 `80+30(Q−1)..80+30Q`，副係數在 `10(Q−1)..60+10Q`，槽數 Q−1（Q1）。這是確定性的編輯器政策，不宣稱模擬原生升品操作。
- 升品須明選所有新增連續尾槽的合法 ID／係數，新增旗標為 0；保留既有重複但禁止新增重複。降品預覽並確認刪除尾槽，清零其 ID／係數／旗標；若移除已選槽則拒絕（Q1、Q4、Q10）。
- y6 不變；若超過目標 `10+5(Q−1)` 上限，提示先用套裝等級功能降低。品質操作不暗中降低等級、不扣資源、不替玩家洗練或重選槽（Q2）。
- y0／1／2／3／7／23／24／25／26／27 與其餘非交易欄保持；y23 是合成材料積分，不能同步成新 Q；y26 保留但不宣稱完整用途已解讀（Q3、Q6）。
- 資訊／預覽／套用重用現有品質操作模式，但以套裝資格及獨立群組分派；普通裝備入口維持原權限。自訂座標、舊 set、批次或其他裝備入口不得繞過閘門。無變更不添歷史，失敗完全回滾；沿用 `editing:equipment:庫別:列號`，品質與等級共用整件累計還原，undo 回前一次交易。
- 不新增任意套裝詞條替換、獨立係數修改、首次鎖槽、積分編輯、合成／物品生成或超限功能。遊戲內後續洗練是驗證對象，並非新增編輯器洗練權限。

### 雙詞條池與套裝等級回歸

`P原` 來自 y27 的原普通範本，`P套` 來自 y1 的套裝範本。合成保留槽；原生洗練 SID 564254928232839／expression 4866 傳目前 y1，隨機池 SID 557896778643212／2390 讀 wp23。兩池不可視為等價（Q3、Q4）。

| 狀態 | 本案政策 |
| --- | --- |
| 既有未選槽 | ID 必須在 P原 |
| 唯一已選槽 | ID 可在 P原 或 P套；保留旗標，不據此聲稱能還原洗練歷史 |
| 升品新增尾槽 | 明選 P原 中未與保留槽重複的 ID，目標 Q 係數，旗標 0 |
| 後續原生洗練 | 接受原生 P套 結果，係數依目前 Q；其他槽及 metadata 不應被該次操作改寫 |

不將兩池聯集套用全部槽；多旗標、品質外槽資料、缺 y27 或來源同階／同部位不符拒絕。新增尾槽採 P原 的可達性依據為「目標 Q 普通裝備取得後再合成」，仍需本案原生生成見證，不能只由集合運算宣稱合法（Q1、Q3、Q10）。

抽出或重用套裝共同資格檢查，讓品質與等級入口對已洗槽採相同政策；等級交易仍只改 y6。必驗原池專有、套裝池專有與交集 ID、無選槽／首次選槽／已洗，以及未選槽誤放 P套 專有 ID 的拒絕案。原生洗練後，重讀存檔由品質及等級 API 檢查，執行升降等級、品質→等級→品質、undo／累計還原及新 PID 讀回（Q2–Q4、Q8、Q9）。

此資格擴張超過舊等級首次證明的原池範圍。兩個既有套裝等級群組須保留原首次證明並增加跨池範圍的獨立原生補證；不能只改摘要或用品質通過取代等級驗證。普通裝備的資格與效果另做回歸。

### 四個獨立群組與閘門

| 庫別／方向 | 群組 | 首次必要覆蓋 |
| --- | --- | --- |
| z7 升品 | `backpackSetEquipmentQualityUpgrade` | 15 種升品轉換、背包 IO 與後續搬入／穿戴 |
| z7 降品 | `backpackSetEquipmentQualityDowngrade` | 15 種降品轉換、刪槽／cap／選槽拒絕及背包 IO |
| z9 升品 | `setEquipmentQualityUpgrade` | 15 種升品轉換，未穿戴與穿戴各自覆蓋 |
| z9 降品 | `setEquipmentQualityDowngrade` | 15 種降品轉換，未穿戴與穿戴、刪槽與互指各自覆蓋 |

四群組預設關閉、各自 `initialProofRequired`。需求表、suite、scenario、proof、遷移 family 及相依一起接線；證明綁 15 來源指紋、最小資料、SID 子樹／expression 語意、最終核心、oracle／runner、manifest、基準與原始結果摘要。按群組重算完整覆蓋，拒絕漏案、重複、錯庫／方向、未知或只有 checks=true 的證據。共享效果矩陣可引用同一相符摘要，但各群組的交易／生命週期不能互代。

只有各自完整首次證明及必要驗收通過才開閘；普通品質、套裝等級與代表遷移均不能代證。核心變更須核對所有已開放群組相依，包含技藝上限與套裝等級；依[遷移維護](../../docs/maintenance/migration.md)、[技藝上限重開](../../docs/maintenance/talents.md)處理失效證明，不以關閉既有功能或只換雜湊規避建置阻擋。

### 四種獨立 oracle

1. **交易：** 獨立推導區間平移、槽數、雙池與 cap，不取被測 core 預覽當答案。核對允許欄位、保留 token／BOM／空白／指數／大型整數／型別，驗無變更、拒絕、undo 與整件還原（Q1–Q4）。
2. **生成可達性：** 原生「特定装备」明確指定 Q/T/主係數，取得合法材料後原位合成，保存起始及目標 Q 的生成履歷。隨機槽不假定同 seed、不得強制改原生結果迎合預期；明選候選依池與生成規則核對，效果另驗。沒有已知確定性原生升降品函式，不杜撰原生品質操作（Q3、Q10）。
3. **效果：** 以 y1 套裝主屬性設定、等階、等級、品質與每槽獨立計算，保留取整順序，核對全部受影響屬性與刷新後角色效果。攻擊 L×Q（SID 287806596379587／5306）、主副重疊與舊效果移除必驗。S、N、部位數及額外套裝加成在品質交易前後保持；原生搬移或穿卸後則依新組合重算（Q5–Q7）。
4. **生命週期：** 載入→刷新／效果→原版存檔→停止→新 PID 讀回；再做原生同槽洗練、成本／全效果、兩 API 資格與等級操作、穿卸／搬移／排序，完成第二輪存讀／新 PID。按實際目的列定位，監看 y0–59 及角色指標；搬移只複製 y0–49，不假定尾十欄也被複製。洗練刷新傳新 ID，必須另確認舊貢獻移除（Q4、Q8–Q10）。

### 基準存檔條件

- 依 `.local/game-sources.json` 的 `preferredDevelopmentSourceId` 定位完整來源與獨立 runtime，核對逐檔 manifest、15 指紋及固定原檔雜湊；沿用相符快取，不重新解包。真實存檔、payload、log、state 全留 repo 外。
- 既有 v2.10 的 1,944 份原生基準僅在摘要與生成履歷吻合時作輸入；它們不等同品質首次證明。缺少目標 Q、來源池、材料或洗練履歷須在獲授權後補取得，不任意編 metadata。
- 保存普通取得→合法 recipe／靈物→合成前後：y27 是同階同部位原範本；y23／26 對上材料，涵蓋 y23≠y5；所有支援列有合法主／副係數、槽數、旗標及 y24／25 狀態。特殊取得值、未知 y26 組合先列未支援。
- z7 owner=0；z9 未穿戴無角色引用，穿戴者 owner 與 z2 部位指標唯一且一致。刻意保留跨庫同列號、y0≠現列與搬移目的列改變案例，不要求 y0 全庫唯一（Q8、Q9）。
- 起點及目標具 `L≤min(cap前,cap後)` 的成功案；另外建立合法起點但目標超 cap 的拒絕案。角色能正常刷新並準備 1–4 部位、同／混積分組合。
- 必須有原生洗練取得套裝池專有 ID 的實際見證與足額成本資源，保存洗前後全槽、旗標、效果與 metadata；驗其他槽保持，再核對品質及等級資格。抽樣、存讀或摘要缺失維持未知，不填通過。

### 介面與驗收界線

沿用品質資訊／預覽模式，清楚顯示庫別、目前／目標 Q、主係數、增刪槽、目標 cap、完整單件效果與套裝積分保持。新增槽只提供 P原 候選；保留已洗的 P套 詞條不得誤顯非法。降品確認在目標改變後重設，阻擋原因可理解。

編輯器驗桌面／390px、真實下載 bytes／重載、直接 file、PWA 離線及更新交接。原版品質顯示、槽數與已選槽停用仍需獨立 UI 驗收，不能用函式數值代替；實際遊戲 UI 操作依當次明確授權，未授權就保留缺口，不宣稱完整驗收或提前開閘。Mac、真實雲端／成就與長時間續玩不列本案已證明範圍。

## 階段與阻擋

A 為靜態資料、共同資格、候選交易、oracle 與 manifest；四群組保持關閉，不啟動遊戲。B 為原生基準、完整矩陣／生命週期、介面、受影響既有功能重驗與首次開閘。兩階段都尚未授權實作。

tasks 的每項工程操作以 30–60 分鐘為目標；全量自動執行時間另記，不承諾一小時跑完。若重用現有工具仍無法維持此粒度，實作前先拆成 A／B 子 SDD，每份至多十條，不以巨大任務一次勾選。來源、雙池可達性或原生結果反證政策時，停止相關開放、記錄差異並回到研究／提案修訂；不自行放寬所有槽、砍掉矩陣或把本提案當作遊戲執行授權。
