# Windows 本機 runtime 補丁研究提案

需求類型：獨立研究提案。此輪交付提案及修改位置，**不製作、套用或發布補丁**。網站 v2.1 的存檔編輯及驗證見 [進階修改研究](../../docs/research/advanced-editing.md)，不把 runtime 改動包進單檔 HTML。

## 2026-10-27 評估與決定

以下優先於本頁其餘段落；原文保留作為 V1.0.10.2 時的紀錄。

- **版本**：重核 V1.0.14.0。SID 不變；`501010543923483` 的 expressions 由 `540`–`557` 位移為 `548`–`565`（資質 548–550、技藝上限 551–559、天賦 560–565），`429172563476993` 由 `558`／`559` 變 `566`／`567`。js 範本會隨改版調整（v2.34 改了 167 穆桂英、179 荊軻的天賦）。
- **範圍**：使用者決定只做自然職業上限的靜態研究，結果見[自然職業等級上限研究](../../docs/research/job-level-cap.md)：只改上限會讓職業係數每級成長變小、未滿級角色變弱，滿級加成幾乎不變，因此單獨解除上限不值得。基礎資質移出範圍（v2.27 丹藥超限已開放給有名角色）；有名角色的天賦與技藝上限維持候選。
- **平台**：若進實驗，改為 Mac 隔離副本先行（沿用現有隱藏原生測試工具），結果不代表 Windows。
- **機制**：有名角色若要做，採改 `js.json` 範本列，網站不動、與網站修改器分開；代價是影響所有存檔與之後的招募複製。
- **分發**：只限自用研究，repo 只放規則與研究，不提供玩家操作入口。

## 問題與目標

V1.0.10.2 會在主布局初始化子事件 SID `875429265663964` 呼叫 `数值更新`（SID `907064845535449`）。它由角色範本重建部分存檔欄位；直接寫入存檔後仍會被原版回填，因此無法用「已修改並可匯出」宣稱效果可持續。2026-10-22 靜態查證回填子事件 `501010543923483` 另要求 `save[r,2,2]>0`，只作用於有名角色範本；範本0一般隨機角色的存檔修改路徑見[功能路線圖](../../docs/research/archive/2026-10-22-feature-roadmap.md#2-一般隨機角色的基礎資質技藝上限與天賦)，尚待隔離驗證。本提案仍涵蓋有名角色與自然職業上限。

另有全局 `职业等级上限=30`（變數 SID `705033508603368`）；它與山寨操練上限不同。需要另行評估可撤銷的 Windows 隔離副本補丁，才能研究個別覆寫策略及自然職業超過30級。

## 靜態修改位置

| 候選 | 原版來源 | 必須研究的關聯 |
| --- | --- | --- |
| 基礎資質 | `数值更新` 子事件 `501010543923483`，expressions `540`–`542`；`save[r,10..12,2] ← js[save[r,2,2],10..12]` | 角色資質上限、丹藥增量及渡劫／重生計算；角色範本共用，不能改一個範本便宣稱只改一人 |
| 九項技藝上限 | 同子事件 expressions `543`–`551`；`save[r,22..30,2] ← js[template,22..30]` | 現有等級／經驗、到達上限的零餘額、重新招募與重生；子事件 `429172563476993` 的 expressions `558`／`559` 還會將低於範本初值的技藝等級補高 |
| 天賦 | 同子事件 expressions `552`–`557`；`js[template,51..56]` 回填到 `save[r,1..3,12]` 及 `save[r,21..23,12]` | 天賦 ID 與對應數值／等級、職業與衍生屬性；`天赋属性计算` SID `778369382997146` 的解讀 |
| 自然職業上限 | 全局 SID `705033508603368`，初值30；`获得职业经验` SID `437350704174070` 的子事件 `507626703493755`／`954653786936917` 讀取該上限 | 山寨操練 cap、職業經驗需求、已習得判定、自動轉職與前置職業門檻；只調 cap 不代表角色自動突破30 |

此清單提供定位，尚未選定「改範本資料」或「阻止特定回填」的實作方式。兩者作用範圍不同，後續實驗須先比較：全範本改動會影響所有同範本角色；略過回填可能留下舊版或不完整資料。預設應採明確、個別功能開關及精確目標，不能用停掉整個 `数值更新` 的方式一併跳過其他遷移。

## 後續實驗的約束

- 僅支援 Windows、V1.0.10.2 相符來源；`data.json` 與 runtime 的精確 SHA-256 必須配對，並核對 catalog 全部來源指紋。未知 build 或不符合預期的事件形狀立即停止，不用字串全域取代。
- 原版遊戲 payload、runtime、原始存檔、備份及 patch state 全部放 repo 外。從原版建立新的隔離遊戲／profile／存檔，不覆蓋 Steam 管理的正式安裝目錄。
- 備份記錄原檔 SHA-256、相對路徑、補丁前後 SHA-256 與規則版本。還原只接受當前檔案等於該次補丁後指紋；若遊戲已更新或人工改檔，停止覆蓋並保留雙方副本。重複套用辨識同次結果，不能累加修改。
- 保留真正的 Steam 原生初始化、帳號身分與授權檢查；隔離測試的 Cloud、成就、統計等寫入沿用本機鏡像。補丁不更換帳號、不偽造擁有權，也不以關閉授權初始化解決啟動問題。
- Steam 更新後重新研究；不要把舊版補丁覆蓋新版。補丁成敗與網站可寫群組分開，Windows 結果也不作為 macOS ARM64 啟動器相容證明。

## 驗收與決策出口

後續獲准實驗時，每個功能在獨立基準副本依序驗證：原版載入 → 套用精確規則 → 修改候選值 → 觀察數值更新 → 原生存檔 → 停止測試程序 → 新 PID 重啟讀回 → 原始檔雜湊不變。記錄重生、重新招募、轉職及再次載入是否重新套回原值；職業上限另取得30→31的自然經驗證據，不能只讀存檔內的31。

合成測試涵蓋來源不符、形狀不符、套用中斷、重複套用、還原衝突及可逆性。若只得到一次畫面變化、未通過重啟，維持研究狀態。成功後才另提實作介面、功能作用範圍、可支援值域與分發方式；本輪不建立網站操作按鈕或改正式安裝。
