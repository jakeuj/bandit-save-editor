# 第二批：裝備品質、詞條與丹藥資質增量

需求類型：新功能。階段：使用者已要求實作既有詞條係數與丹藥增量；品質／替換 ID 仍留在研究。

## 為什麼做

v2.1 已驗證一般裝備等級，但品質與詞條具有額外狀態，丹藥增量也不同於載入時會回填的基礎資質。先確認可持久修改的範圍及生命週期，避免只改畫面數字卻破壞後續洗練、服藥或重生。

## 要改什麼

- 依 V1.0.10.2 原版事件與資料表研究品質、套裝相關品質欄、六組詞條 ID／係數及逐槽洗練旗標；提出有效一般裝備的最小修改範圍。
- 研究三項丹藥資質增量的儲存單位、上限來源、服藥條件、角色重生清除與實際效果。
- 將靜態事實、產品建議、未確認項目及遊戲驗證矩陣分開記錄於[研究筆記](../../docs/research/advanced-editing-batch2.md)。未取得遊戲證明前維持唯讀。
- 後續若實作，沿用具名交易、完整預覽、累計還原、復原一步及精確 token 匯出；自訂座標不得繞過。品質與詞條關聯的復原邊界需涵蓋整件裝備，不能逐欄復原出無效組合。
- 最小候選先排除套裝、飛升、寶物與內丹裝備；詞條先評估保留 ID 調整係數，再評估替換 ID。品質下調若造成等級、詞條數或係數不合法，建議阻擋，不默默刪除或重擲。丹藥先以無結丹引用角色建立基準，動態上限與服藥雙重截限分別驗證。
- 一般與超限、品質與詞條、丹藥各自驗證及開放；不把 v2.1 等級的 1000 上限移用到其他欄位。

## 影響範圍

本輪實作涉及 `scripts/extract-game.cjs`、`src/core.js`、`src/knowledge-ui.js`、catalog／verification、合成測試與隔離驗證工具，通過後才同步 HTML／PWA。正式遊戲安裝、玩家存檔與公開寫入權限保持現況。

本輪編輯器版本為 v2.2，遊戲知識基準維持 V1.0.10.2。

## 本輪確認的實作範圍

詞條限 z9 普通裝備、原版等階1–9／品質2–6／等級上限、既有合法詞條與唯一已洗練槽，只改係數且最多兩位小數。保留旗標；尚未洗練者先回遊戲選槽。丹藥採直接指定非負整數累積增量，1代表0.1點；選擇已持有同類丹藥作上限依據，不扣材料。首輪無結丹／重生紀錄，基礎及天賦與範本一致，完整穿戴無特殊加成；上限採 min(角色顯示上限,丹藥上限)，不模擬服藥雙clamp。兩群組分開驗證，沒有超限選項。
