# 套裝等級

需求類型：新功能。狀態：**2026-10-23 使用者確認，授權 A、B 階段；兩庫首次證明通過後才開放，不提交、不推送**。

日期：2026-10-23。依據[套裝等級研究](../../docs/research/set-equipment-level.md)的 go 結論，規劃可驗證的有限寫入範圍。研究基準為 V1.0.11.2／build 26126719；實作時須重新核對所選完整來源，不把研究版本當成當時安裝版本。公式與 SID／expression 以研究 E1–E9 為準，本提案不複製完整公式。

## 為什麼做

讓玩家調整既有套裝等級，同時保留套裝積分、合成來源與穿戴關聯。歷史 z9 路徑曾接受套裝，卻只有普通裝備證明；不能將其視為本功能基礎。v2.8.1 的排除須保留到套裝自己的證明通過。

靜態來源已能區分 y6 的單件效果與 y23 的套裝積分，並定位原位合成和搬移流程，足以進入實作規劃；原生合法基準、效果比對及存讀生命週期仍未完成。研究的 go 不授權現在開閘。

## 要改什麼

### 寫入與群組

| 庫別 | 獨立群組 | 支援狀態 | 首次證明 |
| --- | --- | --- | --- |
| z7 背包 | `backpackSetEquipmentLevel` | 數量 1、owner=0；角色引用僅指 z9 | 背包本身存讀，另經原生搬入 z9 比對升級與效果 |
| z9 裝備庫 | `setEquipmentLevel` | 未穿戴、或唯一且雙向一致的已穿戴套裝 | 兩種狀態分列結果，涵蓋穿戴中原位合成 |

- 只支援已存在、範本／setLink 對應正確、T1–T9、Q1–Q6、現有與目標等級均為 `1..10+(Q−1)×5` 的合法套裝。合法品質與 metadata 組合須有原生來源依據，不以數字落在範圍內取代生成合法性。
- 只改該件 y6，不扣資源、不建立或轉換套裝，不開放套裝品質、詞條修改、批次升滿或超限。寶物與內丹不在本案。
- 保留 y0、y1、y3、y5、y7、y23／26／27、詞條、旗標與所有非目標原文。y23 不等同品質；y26 保留合成來源值；y27 保留原裝備範本。metadata 缺漏或不符已證明規則時拒絕，不自動補值。
- y0 不要求等於目前列號。已穿戴者核對 z9 y7、角色存在、裝備部位與 z2 的唯一引用；未穿戴者不得被引用。原生搬移只複製 y0–49，y50–59 另列觀察，不推定整列搬移。
- 沿用現有等級操作入口與還原／undo 語意，在核心依裝備種類與庫別分派到獨立套裝資格及群組；具體 helper 命名於實作第一步固定。`resolveField`／`setField`、舊入口及自訂座標均不得繞過限制，普通裝備的排除與證明保持獨立。
- 無變更不新增歷史；失敗不留下部分變更。資訊／預覽／套用與還原流程須有核心及 UI 證據。畫面標明套裝等級、該庫驗證狀態與拒絕原因，不宣稱提高等級會增加套裝積分。

語意依據：研究 E1–E2（上限／升級）、E4–E7（積分／metadata）、E8–E9（搬移／歸屬）。

### 基準存檔條件

實作及隱藏原生測試開始時，先依本機 `.local/game-sources.json` 的 `preferredDevelopmentSourceId` 沿用完整來源及獨立 runtime，核對兩份完整性 manifest 與全部 15 來源指紋。只有分析用途的精簡來源不可執行。來源、runtime、原檔與測試 manifest 雜湊均記入 repo 外證據；公開文件只保留去識別摘要。

基準須由同來源遊戲正常讀取，且符合下列條件；提案階段不取得或準備這些存檔；B 階段已依此條件建立並驗證隔離基準：

1. 原生生成／合成的有效套裝有前後對照，可說明 y23、y26 與 y27 來源。以此建立允許的 metadata 規則；尚無證據的組合不得進成功矩陣。
2. z7、z9 未穿戴、z9 已穿戴三種狀態可重現；背包數量／owner有效；角色存在、部位及雙向唯一指標依 z9 檢查，同列號 z7 不受 z9 指標誤擋。
3. 可涵蓋 T1–T9、Q1–Q6、54 套與 216 範本中的合法組合，保留完整合法詞條／係數。合成案例包括 z7 合成後搬入穿戴，以及 z9 穿戴中原位合成。
4. 有 1／2／3／4 個有效部位、同值／混值 y23、混套及三種效果類型。原生資料沒有六件效果，不製造自然六件案例。
5. 有實際搬移目的空列、可刷新角色及可往返穿卸的條件。搬移按實際目的列及 metadata 重新辨識，不能僅依舊列號或 y0。
6. 可依 T／L 成本準備銅錢不足、恰足、充足與最大升級中途不足情境；魂魄獨立見證。玩家原檔始終唯讀，所有準備及操作在 repo 外隔離副本完成。

若任一合法組合或前置無法成立，先記錄原因並區分「原生不合法」與「尚無證據」。前者改列拒絕案例；後者保留未完成，不以縮減分母宣稱完整通過。擴大／縮小產品範圍須先更新提案。

### 獨立 oracle

| oracle | 預期與比對方式 |
| --- | --- |
| 寫入 | 由獨立 token 差異預期驗只有 y6 改變；保留 BOM、空白、指數與大型整數 literal。拒絕／失敗全檔及歷史不變，驗個別還原、全部還原與逐筆 undo |
| 效果 | 依原始表及研究 E4–E6 獨立計算主屬性／詞條、每部位最大 y23、積分 S、件數 N、2／4 件啟用與三類套裝加成；與原生 `装备属性计算` 及刷新角色結果比較，不以被測核心預覽當答案 |
| 升級／成本 | z9 同起點原生單次／最大升級比對上限與逐次銅錢成本，魂魄保持。編輯器不扣資源，所以裝備／效果相同與資源差異分開斷言。z7 先核對背包輸出，再原生搬入取得目的列後比較，不直接呼叫 z9 函式處理背包列 |
| IO／生命週期 | 載入、刷新、原版存檔、停止、新 PID 讀回；再涵蓋搬入、穿戴、卸下、搬回及兩庫合成路徑。原生側使用明確允許差異清單，不要求整份存檔 bytes 不變；每階段有有效前置、實際效果及 PID／存檔雜湊鏈 |

降級沒有原生降級函式可直接對照：以合法低等級基準的原生效果、編輯結果存讀與後續再升級驗證，不把原生升級說成降級證明。效果因取整而相同可接受，須符合獨立公式；要求的是 y6 相依計算正確，並非每項效果必須數值增加。只改 y6 時 S、N 與套裝額外加成應保持；若原生結果推翻此推論，停用相關群組並回研究修正。

### 首次矩陣與執行方式

| 矩陣 | 規模／分配 | 必要觀察 |
| --- | --- | --- |
| 全範本邊界 | 216×6 品質×4 轉換×3 狀態＝15,552 案；z7 5,184 案、z9 10,368 案 | 轉換為 1→2、2→1、cap−1→cap、cap→cap−1；每案驗寫入、metadata 與效果，按庫分 manifest |
| 套裝效果 | 54×4 部位狀態×2 積分配置×2 等級方向＝864 案 | 1／2／3／4 部位、同值／混值；透過 z9 原生效果比對，z7 搬入後亦須有可追溯對照，不用這 864 案取代 z7 存讀 |
| IO／搬移／合成 | 至少 12 副本＝3 狀態×Q1/Q6×升/降；其中 z7 至少 4、z9 至少 8 | 每副本原版存檔／新 PID；全體覆蓋 T1/T9、三類效果、兩庫合成及搬移往返；無法覆蓋時加副本 |
| 成本／拒絕 | 另列具名案例，不併入前三列數量 | 不足／恰足／充足／中途不足、封頂再升、Q0/Q7、非法等級／metadata、錯 owner／部位／重複引用、非套裝、非法庫別與唯讀繞過 |

這些是首次目標估計，不是已有通過數。先依基準來源列出合法／拒絕／未知清單，再固定 manifest 及每庫覆蓋。矩陣工具須能按範本／品質／狀態分片，持久化已完成案例、來源與輸入／oracle 摘要；相同輸入才可續跑，漏案、重複案例、跨版本拼接與失敗不得算完整。自動執行耗時未知，不能承諾一小時內跑完；先測量小片再估全量，不用代表遷移替代首次矩陣。

### 證明與開放規則

- 新增需求 section、family、代表情境與相依宣告；兩庫均須 `initialProofRequired`，各自綁定完整來源、最小資料、SID 子樹、公式／最終核心摘要及完整矩陣／IO 結果。`tz` 未變不等於其他相依未變。
- catalog 新增最小套裝資料：`tz` ID／名稱／件數、效果對、成員範本，搭配 `wp` setLink／部位／等階／主屬性與 `sx` 類型。未知欄位不猜測；不複製完整 payload。尚無證明時新群組預設關閉。
- 開放條件為各庫完整首次證明通過且摘要相符；一庫失敗只維持該庫關閉，通過庫仍須完成其自身全部驗收。首次完整證明與日後代表遷移分開保存。
- 核心定稿後才取得最終證明；任何 core 變動須依[維護指引](../../docs/maintenance.md)處理 `randomCharacterSkillCaps` 的整檔摘要與受影響舊群組。不得只替換摘要冒充重驗；非受影響舊證明保留，合併或建置失敗回滾。
- 編輯器新增操作需完成桌面／390px、下載 bytes／重新載入、直接 file 及 PWA 離線／更新流程的適用案例。遊戲 UI 不作本案宣稱；原生函式證據與 UI 證據分開。若後續需要桌面操作，另依使用者明確指示處理。
- 本案不預定版號，不包含提交、推送或發布。發布前仍須按實際範圍更新文件及完成當時必要驗收；不發布既有群組因摘要失效而被關閉的中間狀態。

## 分階段與阻擋處理

先做 A：基準規則、資料、核心與 oracle／驗證工具；再做 B：完整首次矩陣、生命週期、介面及真證明開閘。A 已完成候選核心與工具；B 已依續作授權完成首次原生證明與驗收，結果見 tasks。tasks 將設計／開發切成最多十個工作項；每次操作以 30–60 分鐘為界，自動矩陣另按分片續跑。若工具實作預估仍超過一小時，開工前先將 A／B 拆成各自的 SDD，不把大工作硬塞成單一步驟。

來源、合法基準或原生結果受阻時記錄具體缺口，不降低首次證明要求。A、B 已分別取得授權；沿用完整快取做隱藏／靜音隔離測試，未操作遊戲桌面。兩個群組在各自完整首次證明通過後才開放，未提交、推送或發布。
